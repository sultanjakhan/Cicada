# Cicada

[English version](README.md)

Cicada — планировщик целей, задач, календаря и заметок, который хранит данные у вас. Всё лежит в файле SQLite на устройстве: без аккаунта, облака и телеметрии. Если устройств несколько, можно поднять собственный relay для синхронизации со сквозным шифрованием.

Tauri 2 · Rust · SQLite · JavaScript. Лицензия [MIT](LICENSE), лицензии сторонних компонентов — в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md).

> **Статус:** ранняя версия (0.x), один сопровождающий. Интерфейс только на русском.
> Платформы: Windows x64, macOS на Apple Silicon, Android ARM64. Linux пока не поддерживается.

## Что есть

- **Дашборд** — выбранная цель, текущая задача и таймер работы.
- **Календарь** — день, неделя и месяц; общий переключатель «Задача / Событие».
- **Задачи** — активные, на сегодня, без даты и завершённые; поиск и фильтр по цели, включая подцели.
- **Цели** — подцели, критерии результата, навыки и этапы со сроками, связи с задачами и событиями.
- **Заметки** — явное сохранение черновика, архив и восстановление.
- **Рутины** — повторяющиеся действия, которые запускаются и отмечаются из календаря.
- **Сон и активность** на Android — импорт из Health Connect, подробнее в [описании импорта сна](docs/sleep-import.md).

## Установить

Скачайте файл из [последнего релиза](https://github.com/sultanjakhan/Cicada/releases/latest):

- **Windows x64** — `Cicada-<версия>-windows-x86_64.exe`. У установщика нет сертификата Authenticode, поэтому SmartScreen может предупредить: «Подробнее → Выполнить в любом случае».
- **macOS, Apple Silicon** — `Cicada-<версия>-darwin-aarch64.app.tar.gz` с `Cicada.app` внутри. Первый запуск описан в [инструкции для macOS](docs/macos-build.md).
- **Android ARM64** — `Cicada-<версия>-android-aarch64.apk`; разрешите установку из выбранного источника.

Новый профиль пустой, аккаунт не нужен. Обновления сохраняют данные.

Приложение проверяет подпись обновлений перед установкой. Windows откладывает установку, пока приложение используется; Android может попросить системное подтверждение. Это подпись канала обновлений, а не сертификат Windows Authenticode и не публикация в Google Play.

## Собрать из исходников

Нужны Node.js 22.12+, Rust 1.98+ и Python 3. На Windows также Visual Studio Build Tools с C++ и WebView2, на macOS — Xcode Command Line Tools. Сборка для Android — в [android-build.md](docs/android-build.md).

```sh
git clone https://github.com/sultanjakhan/Cicada.git
cd Cicada
npm ci
git config core.hooksPath .githooks
npm run tauri dev
```

В Windows PowerShell вместо `npm` используйте `npm.cmd`. Интерфейс работает через native IPC приложения Tauri; `npm run dev` запускает только сервер ресурсов, браузер не подменяет локальную базу тестовыми данными.

В debug-сборке переменная `HANNI_MVP_DATA_DIR` с абсолютным путём задаёт отдельный тестовый профиль. Данные обычной Hanni приложение не читает и не изменяет.

Пакеты собираются из чистого коммита: `npm run package:windows` на Windows (NSIS-установщик и manifest в `.local/windows-package/<sha>/`) или `npm run package:mac` на Mac.

## Проверки

```sh
npm test
npm run build
cargo test --manifest-path src-tauri/Cargo.toml --locked
npm run check:privacy
```

`npm run check:history` проверяет также все достижимые коммиты и их метаданные. Privacy guard ищет в текстовых файлах типовые личные данные и секреты; дополнительные приватные строки передаются через `--denylist` из локального JSON вне Git. Guard выводит только путь, строку и тип находки. Он не доказывает отсутствие всех возможных личных данных.

Обмен между нативными тестовыми базами через локальный Cloudflare runtime проверяется так:

```sh
npm --prefix sync-relay ci
npm --prefix sync-relay test
npm --prefix sync-relay run test:native
```

Этот прогон использует вымышленные записи и временные ключи и не подключается к облачной учётной записи.

JSDOM-тесты проверяют сборку интерфейса, переходы между вкладками, формы, черновики заметок, цели и обработку ошибок. Rust-тесты проверяют хранение, миграции и резервные копии. Это не заменяет проверку установленного приложения на Windows, Mac и Android.

## Данные и резервные копии

База `calendar.db` лежит в каталоге данных приложения, на Windows — `%APPDATA%\app.hanni.mvp`. Обновление переносит записи через транзакционную миграцию. Таблица `items` хранит задачи, события и заметки; отдельные таблицы — цели, связи целей, категории, интервалы работы и настройки интерфейса. Время календаря — местное время устройства.

Команда `create_backup` сохраняет копию в подкаталог `backups` через SQLite online backup с проверкой целостности.

Старые версии не читают новую схему базы, поэтому откатывать приложение нужно вместе с резервной копией, сделанной до обновления. Для восстановления закройте Cicada, сохраните текущую базу и её файлы `-wal`/`-shm` отдельно, затем положите выбранную копию как `calendar.db` без старых `-wal`/`-shm` рядом. Встроенного восстановления пока нет.

## Синхронизация устройств

Синхронизация необязательна. На каждом устройстве нужна совместимая версия Cicada и свой код подключения; сервер и коды готовятся по [руководству relay](docs/sync-relay.md). Обычная Hanni использует другую схему данных и в обмен не входит.

В настройках откройте «Синхронизация», вставьте код устройства и сохраните. Перед первым включением создаётся проверенная резервная копия. В обмен входят записи календаря, цели и их связи, интервалы работы, начало дня, развитие навыков и повторяющиеся действия. Настройки окна, локальные предпочтения и секреты устройств не синхронизируются.

Без сети приложение работает с локальной базой и копит изменения для отправки. Статус показывает очередь и ошибки текущего устройства; успешная отправка ещё не значит, что другое устройство получило запись. Пока открыт редактор, автоматическое обновление экрана откладывается. Сохранённые альтернативные версии можно посмотреть и выбрать в настройках синхронизации.

Журнал relay ограничен 128 МиБ или 100 000 пакетов. При заполнении он отклоняет новые отправки, а неподтверждённые изменения остаются на устройстве. Контрольные снимки и очистка подтверждённой части журнала реализованы, но выключены по умолчанию; включение описано в [правилах relay](docs/sync-relay.md).

## Структура

- `src/` — оболочка (`app.js`, `index.html`) и компоненты интерфейса в `src/hanni/`.
- `src-tauri/` — Rust: запуск, база, миграции, резервные копии, синхронизация, обновления.
- `src-tauri/plugins/android-installer/` — Android-плагин: обновления и Health Connect.
- `sync-relay/` — Cloudflare Worker для зашифрованной синхронизации.
- `update-service/` — Cloudflare Worker, раздающий подписанные манифесты обновлений.
- `scripts/` — упаковка, генерация иконок и проверки приватности.

Знак «цикада / песочные часы» хранится в `src/app-icon.svg`. Команда `python3 scripts/generate-icons.py` обновляет иконки в `src-tauri/icons/`, включая слои тематической иконки Android.

## Происхождение и неизменяемые имена

Cicada выросла из личного приложения автора Hanni. Видимое имя продукта — Cicada, но техническая идентичность сохраняется ради обновлений и данных: `app.hanni.mvp`, `hanni-mvp.exe`, каталог установки `%LOCALAPPDATA%\Programs\Hanni MVP`. Менять эти имена нельзя: установленные копии перестанут обновляться и потеряют доступ к данным.
