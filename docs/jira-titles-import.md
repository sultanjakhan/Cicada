# Jira: названия и статусы задач

Настройки Cicada → Подключения → Jira. Коннектор на Mac или Windows читает
все доступные аккаунту задачи выбранного проекта независимо от исполнителя
и статуса, включая завершённые (до 500 за проход).
Сохранение подключения запускает первую загрузку. Затем проверка выполняется
при открытом приложении не чаще раза в 15 минут; есть «Обновить».
Импорт ничего не меняет в Jira. Переименование и переход в другой статус
выполняются отдельными кнопками в карточке задачи.

## Подключение

1. Создай [API-токен Atlassian](https://id.atlassian.com/manage-profile/security/api-tokens).
   Выбери создание токена со scopes, приложение Jira и два права типа Classic:
   `read:jira-work` и `write:jira-work`. Это полный набор для загрузки,
   создания, переименования и смены статуса задач в Cicada.
   Чтение описано в [контракте поиска](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issue-search/#api-rest-api-3-search-jql-get),
   запись — в [Edit issue и Transition issue](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issues/).
   Для одного чтения достаточно `read:jira-work`. Названия scope-категорий
   Classic/Granular не определяют тип токена в настройках Cicada.
   `write:jira-work` также покрывает [Create issue](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issues/#api-rest-api-3-issue-post);
   дополнительно выбирать Granular scopes не нужно. Коннектор не использует
   комментарии и вложения; scopes самого токена шире полей запроса.
   Права готового токена не редактируются: если набор неполный, создай новый.
2. В «Настройках подключения» введи сайт вида `example.atlassian.net`, email аккаунта,
   сам токен и ключ проекта, например `DEMO`.
   Тип «С правами (scopes)» выбран по умолчанию; для токена без scopes измени
   его в «Дополнительных». Нажми «Сохранить и подключить».
   Токен вводится только в приложении, не в чате, репозитории или Issue.
3. Проверь результат загрузки в этом же разделе; названия появятся в рабочих
   задачах с отдельным статусом Jira, без назначенного процесса и этапа. Пустой результат может означать,
   что подходящих задач нет или у аккаунта нет права их видеть.

Поле токена очищается после сохранения: секрет остаётся в системном хранилище.
После успешной загрузки поля сворачиваются: остаются сайт, проект, результат
загрузки и «Обновить». Для замены токена раскрой «Настройки подключения»;
кнопка «Изменить» у адреса открывает сайт и проект. Сворачивание полей и фоновая
загрузка не стирают несохранённый ввод. Ошибка авторизации раскрывает настройки,
а ошибка scopes — также инструкцию и тип токена.
Сохранение и успешное подключение показаны раздельно. Несовпадение scopes,
отказ авторизации и недоступность локального ключа имеют разные сообщения.
Весь сценарий выполняется в настройках Cicada, без Terminal и отдельных окон
ввода токена или пароля Mac.

На Mac новая локальная сборка может потерять доступ к Keychain-записи предыдущей
сборки. При явном вводе нового токена Cicada создаёт свою защищённую запись,
проверяет чтение и только затем атомарно сохраняет её UUID в локальном файле
`jira-import.keychain-slot` рядом с базой. Этот файл не содержит токена или email
и не синхронизируется. Прежние записи и их права доступа не меняются.
После отключения указатель сохраняется, чтобы старый токен не подключился снова.
Это восстановление через новый токен, а не перенос доступа между подписями;
старые версии Cicada этот указатель не понимают. Хранилище ключа синхронизации
устройств остаётся отдельным.

Токены [со scopes](https://support.atlassian.com/atlassian-account/docs/manage-api-tokens-for-your-atlassian-account/)
используют `api.atlassian.com/ex/jira/{cloudId}`; обычные — выбранный сайт.
Для scopes идентификатор сайта определяется через официальный
[`/_edge/tenant_info`](https://support.atlassian.com/jira/kb/retrieve-my-atlassian-sites-cloud-id/)
без отправки токена. При смене сайта или типа подключения токен нужно ввести
заново. На телефоне прямое подключение недоступно; названия и статусы могут прийти через
синхронизацию Cicada. Подключай импорт на одном компьютере, чтобы параллельные
переименования не создавали конфликты синхронизации.

## Что хранится и передаётся

| Данные | Обработка |
| --- | --- |
| Название (`summary`) | Сохраняется как название обычной рабочей задачи. Участвует в существующей синхронизации и резервных копиях Cicada. |
| Название статуса | Сохраняется отдельно от локального этапа и завершения. Участвует в синхронизации и резервных копиях. |
| Описание, комментарии, вложения, люди | Не запрашиваются и не сохраняются; ответ с дополнительными полями внутри `fields` отклоняется до записи. |
| Ключ задачи, ссылка Jira | Не сохраняются и не показываются на карточке. |
| Jira ID | Только в памяти для вычисления устойчивого хеша вместе с сайтом. В базе и синхронизации остаётся производный технический ID задачи. |
| Доступные переходы | Читаются при открытии редактора. Их технические ID нужны только для выбора перехода и не сохраняются в задачах или синхронизации. |
| Сайт, проект, тип токена, время/результат проверки | Локальные настройки устройства; не входят в синхронизацию задач. Полная резервная копия локальной базы содержит эти настройки. |
| Email и API-токен | Системное хранилище секретов (Keychain на Mac); не база задач, не синхронизация, не резервная копия базы. Email отображается в настройках подключения; сохранённый токен обратно в интерфейс не возвращается. |

Запрос поиска использует только `fields=summary,status`. Из объекта статуса
сохраняется только название. Ответ Jira целиком не попадает
в JavaScript, логи или текст ошибки. Редиректы отключены; TLS проверяется;
учётные данные отправляются только в Atlassian по выбранному маршруту.
Производный ID предотвращает дубли, но не является гарантией анонимности.

Ограничение до названий и статусов обеспечивает код коннектора: scopes токена
не ограничивают доступ отдельными полями или одним проектом. Для ограничения
доступа самим сервером нужна учётная запись с правами только на нужный проект.
Это также не защита от программы
с доступом к учётной записи Mac или от секретов, уже написанных в самом названии.
Коннектор не подключает Jira напрямую к внешнему AI. Agent City получает только
те данные задач, которые уже сохранены в Cicada, в пределах своего подключения.

## Изменение в Jira

Открой импортированную задачу → «Изменить в Jira». Диалог отдельно показывает
актуальное название и статус Jira. «Сохранить название в Jira» отправляет только
новое название; «Изменить статус в Jira» — только выбранный доступный переход.
Локальная кнопка «Редактировать», завершение, этапы и таймеры Jira не меняют.
Аккаунту нужны права Browse Projects, Edit Issues и Transition Issues;
scopes не заменяют права пользователя и правила workflow.

Перед записью коннектор заново проверяет принадлежность задачи выбранному
проекту и прежнее значение. При обнаруженном изменении запись отклоняется:
обнови состояние и проверь черновик. Между проверкой и записью остаётся короткое
окно конкурентного изменения — Jira не даёт этому сценарию атомарной проверки.
После отправки выполняется чтение задачи для подтверждения результата.
Если ответ потерян, автоматического повтора нет: сначала «Обновить из Jira».
Переходы, требующие дополнительных полей, выполняются в самой Jira.

Несохранённое название сохраняется при обновлении состояния и смене статуса.
Закрытие редактора требует сохранить изменение или отменить черновик.
Смена статуса Jira не запускает таймер, не меняет процесс и не завершает задачу
в Cicada. Если у задачи уже есть ручное локальное название, оно сохраняется
даже после явного переименования в Jira; удалённое название видно в диалоге Jira.

## Создание задачи

«Создать → Задача → Рабочая» загружает доступные типы задач выбранного проекта.
Введи название, выбери тип и нажми «Создать в Jira». `BE: …` остаётся названием.
В Jira отправляются только проект, тип и название; статус берётся из результата.
Дополнительные дата, время, цель и процесс сохраняются в Cicada и не меняют Jira.
«Личная» создаёт только локальную задачу. Редактирование уже существующей
локальной задачи не создаёт ей копию в Jira.

Нужны права Browse Projects и Create Issues. Подзадачи и типы с дополнительными
обязательными полями без значения по умолчанию нужно создавать в самой Jira.
Метаданные типов и требований полей обрабатываются временно; интерфейс получает
только ID/названия типов. Рабочие описания и люди не импортируются.

Локальный журнал защищает от повторной отправки после обрыва ответа или перезапуска.
При неизвестном результате проверь задачу в Jira и нажми «Обновить» в подключении.
Только после проверки нажимай «Проверил Jira — разрешить новое создание»:
новая отправка действительно создаёт новую задачу. По совпадению названия задачи
автоматически не склеиваются. Если журнал подтвердил создание, форма показывает
уже созданную задачу и завершает подтверждение без нового запроса создания.
Журнал содержит разрешённое название, производные идентификаторы и состояние
операции, не содержит ключа/URL Jira или токена и не участвует в синхронизации.

## Повторная загрузка и отключение

Обновление названия из Jira применяется, если название в Cicada осталось таким,
каким его сохранил предыдущий импорт. Ручное переименование, завершение,
удаление, выбранные этапы и учёт времени сохраняются. Исчезновение задачи из
поиска Jira не удаляет и не завершает её в Cicada. За один проход обрабатываются
до 500 задач; при ограничении это видно в состоянии импорта.

«Отключить» останавливает импорт и удаляет сохранённые учётные данные.
Уже импортированные задачи остаются. При ошибке удаления токена интерфейс
сообщает об этом отдельно; импорт при этом остановлен.

Проверки разработки используют вымышленные ответы Jira и изолированные базы.
Они подтверждают формат запросов, отсутствие запрещённых полей в сохранении
и синхронизации, повторные загрузки и ошибки; доступ к реальному проекту
проверяется отдельно после ввода токена пользователем.
