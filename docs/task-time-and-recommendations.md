# Задачи в работе, таймер и рекомендации

Решение владельца от 28.09.2026. Связанные задачи разработки: [#104](https://github.com/sultanjakhan/hanni-tasks/issues/104), [#101](https://github.com/sultanjakhan/hanni-tasks/issues/101), [#107](https://github.com/sultanjakhan/hanni-tasks/issues/107).

## Что считает таймер

«Время работы» — сумма времени всех запусков конкретной задачи в Cicada, включая
текущий запуск. ▶ начинает отсчёт, пауза останавливает его, повторное нажатие ▶
продолжает накопление. Перерывы не учитываются. Например, 10 минут работы,
полчаса паузы и ещё 5 минут работы дают 15 минут.

До первого запуска показано `00:00`. Формат — минуты и секунды; после часа —
часы, минуты и секунды. Если у задачи есть оценка, она показана рядом с фактическим
временем под подписью «Время работы / оценка». Оценка не ограничивает таймер.

В списке «В работе» у задачи один счётчик — за всю задачу и все дни. Смена
внутреннего этапа его не обнуляет. Разбивка времени по этапам остаётся в карточке
задачи и подсказке этапа; отдельной строки «Учтено на этапе» на дашборде нет.

Таймер каждой задачи управляется отдельно. Несколько таймеров могут работать
одновременно, поэтому сумма времени разных задач может превышать прошедшее
время по часам. Нажатие на название открывает карточку, не меняя таймеры.

## Как связаны Jira, внутренние этапы и запуск

| Действие | Результат |
| --- | --- |
| Импорт задачи In Progress | Задача появляется в «В работе». Учёт времени начнётся после ▶. |
| «Начать» у доступной рабочей задачи | Cicada сначала подтверждает рабочий статус в Jira, затем запускает локальный таймер этой задачи. При ошибке Jira таймер не запускается. |
| Пауза | Останавливается только таймер выбранной задачи. Статус Jira сохраняется. |
| «Дальше» у внутреннего этапа | Меняется этап Cicada. Статус Jira, состояние таймера и накопленное время не меняются. |
| Изменение статуса через Jira и последующий импорт | Обновляется статус. Импорт не запускает таймер и не восстанавливает прошлое время из истории статуса. Уже работающий таймер остаётся доступен для паузы. |

Роль статуса задаётся в «Настройки → Процессы задач». Cicada не угадывает её по
названию или категории Jira. Для текущего рабочего процесса To Do означает
«к выполнению», In Progress — «в работе», Backlog — «завершено» по выбору владельца.
Внутренний процесс необязателен; у задачи без процесса остаются статус и таймер.

## Когда появляется рекомендация

Пока есть хотя бы одна текущая задача, предложение нового дела скрыто.
Это правило действует и для одной задачи, и для четырёх; наличие работающего
таймера не является обязательным.

| Состояние | Что видно на дашборде |
| --- | --- |
| Есть задачи с работающими таймерами | Один список «В работе · N», отдельные кнопки паузы. Новая задача не рекомендуется. |
| Есть начатые задачи, но таймеры на паузе или ещё не запускались | Тот же список с ▶ у каждой задачи. Пользователь выбирает, какую продолжить; одна из них автоматически не назначается. |
| Текущих задач нет | Рекомендация из доступных задач и рутин по настройкам рекомендаций; если подходящих нет, пустое состояние. |
| Пользователь хочет взять ещё задачу | Постоянная кнопка ▶ открывает выбор. Новая задача запускается только по явному действию. |
| Список ещё загружается или чтение завершилось ошибкой | Рекомендация скрыта: отсутствие ответа не означает отсутствие текущих задач. |

В список входят доступные незавершённые Jira-задачи с ролью «в работе», даже
без локальных запусков, а также текущее выполнение Cicada. Локальные задачи
на паузе показываются, если над ними работали сегодня. Jira-задача на паузе
выходит из списка после перехода в другую роль, например на ревью или в завершённые.
Если её таймер ещё идёт, строка сохраняется, чтобы его можно было остановить.

Все строки находятся в одном блоке; одна задача не выносится отдельно сверху.
Число в заголовке совпадает с числом строк. Запуск, пауза и открытие карточки
не переставляют строки. Отдельно открытое выполнение рутины также подавляет
рекомендацию нового дела.

## Проверка и установка

Правила выше описывают согласованное поведение. Проверка на вымышленных данных
в отдельной native-сборке не означает установку в основную Cicada и не подтверждает
успешный запрос к рабочей Jira.

Текущая установка подписана ad-hoc: доступ к сохранённому токену привязан к её
конкретному исполняемому файлу. Обновление требует отдельно решённого переноса
доступа или явно согласованного повторного подключения. Документирование и
проверка интерфейса сами по себе эту проблему не устраняют.
