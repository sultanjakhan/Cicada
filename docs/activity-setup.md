# Учёт приложений и восстановление

ActivityWatch считает использование приложений. Cicada собирает дневные итоги в
обычные события существующего календаря. Ответы о восстановлении и соблюдении
личного правила вводит сам человек в рутине. Из статистики приложений эти ответы
не выводятся.

## Подключение

Открой **Настройки → Ограничения → Добавить устройство**. Укажи понятное название,
систему и локальный порт ActivityWatch. Подключение и его ключ сохраняются только
на этом устройстве. После сохранения можно импортировать данные вручную или
включить автоматическое обновление, пока Cicada работает.

На Windows сборщик ActivityWatch должен исключать заголовки окон: у
`aw-watcher-window` требуется `exclude_title = true`. Импорт проверяет это по
самим событиям. При обнаружении заголовка он прекращается с ошибкой; ранее
сохранённые дневные итоги остаются. Расширение для отслеживания страниц браузера
не требуется. Снимки экрана, нажатия клавиш, адреса страниц и содержимое документов
в этот сценарий не входят.

На Android ActivityWatch использует системный доступ к статистике использования.
Его API может требовать ключ. Для чтения с ПК через USB требуется разрешённое
ADB-подключение и перенаправление локального порта. После отключения телефона
источник станет недоступен; это не означает нулевое использование. Наличие
коннектора в коде не подтверждает работу конкретной Android-сборки Cicada.

Для дня и подключения создаётся одно событие без назначенного часа. Повторный
импорт обновляет тот же итог. Это сумма интервалов за день, поэтому её нельзя
показывать как одно непрерывное занятие. На двух устройствах использование может
пересекаться: складывать их как уникальное время человека нельзя.

**Приложение на переднем плане** не равно вниманию. **Без статуса AFK** означает
сигнал сборщика об отсутствии длительного простоя ввода; просмотр видео может
попасть в AFK. Если источник не предоставляет этот сигнал, значение неизвестно.
Неполный день нельзя напрямую сравнивать с полным.

## Рефлексия

В редакторе рутины выбери одно дело без таймера и включи короткую рефлексию в
дополнительных настройках. Вопрос принадлежит твоим данным; личные правила не
включаются в установку. В деталях рутины можно сохранить ответ за выбранный
наступивший день, отметить восстановление и при желании кратко назвать триггер.
Ответы можно исправить. «Нет ответа» не означает нарушение правила.

Заполнение рефлексии и отметка выполнения рутины — отдельные действия. Отметка
выполнения не должна удалять уже сохранённые ответы.

## Где хранятся данные

- Сырые события остаются в ActivityWatch. Cicada сохраняет только дневное время
  по приложениям и устройство, указанное в настройке подключения.
- Дневные события используют существующую синхронизацию календаря, если она
  настроена. Ответы рефлексии используют существующее хранилище рутин.
- Настройки соединения и ключ API не становятся календарными событиями и не
  синхронизируются. На Windows ключ защищается DPAPI текущего пользователя;
  это не защита от всех программ, запущенных от его имени.
- Приостановка автоимпорта останавливает новые импорты в Cicada. Сам сборщик
  ActivityWatch управляется отдельно в его приложении или системных разрешениях.

Для рабочего Mac требуется отдельно проверить настройки его сборщика. Проверка
Windows не доказывает отсутствие заголовков и путей в данных Mac.

## Блокировщики и каталог

Agent City хранит ссылки и назначение инструментов. Сохранение карточки не
устанавливает программу и не включает ограничения.

[TimeLimit](https://timelimit.io/en/) — кандидат для групп приложений и расписаний
на Android; [LeechBlock NG](https://github.com/proginosko/LeechBlockNG) — для правил
в поддерживаемом браузере. Их ограничения настраиваются в самих инструментах.
Наличие приложения не доказывает, что правило действует: нужна проверка
запрещённого и разрешённого действия на соответствующем устройстве.

Для поиска альтернатив подходит [AlternativeTo](https://alternativeto.net/).
Открытость и поддерживаемые системы затем проверяются в официальном репозитории
и документации, а не только по метке поискового каталога.

При проверке исходников Focuser v0.8.0 обнаружено, что CLI использует `NoopSync`:
успешная команда управления списком сама по себе не применяет системную
блокировку. Этот путь не принят как автоматическое управление защитой.

Ни один из этих компонентов не запускает помощника для постоянного наблюдения
или ежедневных сообщений. Автоматический импорт выполняет Cicada, а не чат.
