# Контекст продукта Cicada

Этот документ фиксирует подтверждённый контекст независимого продукта Cicada.
Перед новой постановкой или изменением сначала прочитай его, исходный код и
относящиеся к задаче Issues. Уточняй только действительно новые факты, которых
там нет.

## Проект и название

Cicada — самостоятельный проект. Он не является legacy Hanni и не использует его
репозитории, блокировки записи, данные, учётные данные или релизы.

Пользователь однозначно выбрал латинское название **Cicada** и разрешил переименовать
display name и независимый репозиторий. Канонический URL —
`https://github.com/sultanjakhan/Cicada`. Не использовать «Цикада» и не оставлять
«MVP» в display name. Остальной интерфейс остаётся на русском.

Техническая идентичность пока сохраняется: bundle identifier, package name,
stored keys, DOM IDs, custom event names, JS global identifiers, Android
package/security identifiers и подписывающие ключи не переименовывать без
отдельного решения. Лицензии и third-party attribution сохранять.

## Подтверждённый путь здоровья

Ожидаемая цепочка выглядит так:

`Samsung Health или совместимое приложение, которое пользователь может назвать «google health» → Android Health Connect → импорт в MVP → зашифрованная синхронизация → Calendar на Mac/Windows`

«Google health» — это формулировка пользователя. По ней нельзя самостоятельно заключать, что источником является конкретное приложение Google Fit. Samsung Health или другое приложение сначала должно передать данные в Health Connect; наличие данных только в источнике само по себе не доказывает, что их может прочитать MVP. Технические детали импорта и синхронизации описаны в [импорте сна](sleep-import.md) и [реле синхронизации](sync-relay.md).

## Границы текущего здоровья

Подтверждённый ожидаемый охват — сон, прогулки и шаги. Наличие реализации и выпуск каждой возможности проверяются отдельно по текущему исходному коду и релизу. Не добавляй и не придумывай показатели здоровья или числовые значения, которых нет в источнике или подтверждённом контексте.

Пользователь хочет мобильный календарь позднее, после исправления синхронизации с Mac. Это последующее направление, а не разрешение расширять текущую задачу без отдельного решения.

## Положение окна на Mac

При закрытии и повторном запуске Cicada возвращает главное окно на последний
выбранный физический экран при неизменной расстановке дисплеев и восстанавливает
его размер и положение. Это также относится к окну, которое пользователь открыл
после запуска с `--minimized` или
`--background`. Одноразовые команды без окна (`--sync-check`, `--configure-sync`,
`--update-background`) не меняют сохранённое положение. Если экран отключён,
окно должно остаться видимым на доступном экране. Настройки разных локальных
профилей, а также DEV и release, не смешиваются. Восстановление macOS Spaces
не входит в этот критерий. Небольшое перекрытие верхнего края системным меню
не сбрасывает последнее положение, пока область заголовка доступна.

## Текущая задача в шапке

22.09.2026 пользователь выбрал компактный блок текущей задачи справа в общей
шапке во всех разделах. Без выбранной задачи скрывается только этот блок.
Постоянная кнопка «Запустить задачу» сверху рядом с «Новая задача» открывает
выбор из незавершённых задач, включая задачи без цели и даты. Открытие списка
или деталей само по себе не запускает задачу. Название выбранной задачи справа
открывает её детали; рядом доступны запуск, продолжение или пауза той же задачи.
Большую плашку текущей задачи на дашборде убрать, сохранив блок цели.

## Правила дальнейшей работы

Пользователь предпочитает, чтобы код редактировали native subagents; root отвечает за постановку, границы и приёмку результата. Не создавай второй backlog или отдельную фиктивную систему статусов поверх существующих Issues.

UI-правки показывать и проверять в нативном DEV Cicada; браузерный preview не использовать вместо DEV. Не запускать, не фокусировать и не перезапускать окно владельца сверх выданного разрешения.
