# Импорт цифровой активности: IPC-контракт

Настройки «Ограничения». В новом профиле подключений нет. API команд — camelCase.

## Команды

- `digital_activity_get_connections()` → `{ enabled, devices }`.
- `digital_activity_save_connection({ input: { id?, label, source, endpoint?, port, enabled, token? } })` → `{ id, saved: true }`.
- `digital_activity_remove_connection({ deviceId })` → `{ id, removed: true }`. Удаляет подключение и его локальные ключи/статус, сохраняет исторические события календаря. Не останавливает сам ActivityWatch.
- `digital_activity_import_now({ deviceId?, localDate? })` → `{ imported, changed, skipped, errors: [{ deviceId, error }], days }`.
- `digital_activity_status()` → `{ enabled, devices }`.

`enabled` управляет автоматическим импортом раз в минуту. Ручной импорт разрешён и для приостановленного подключения. Без `localDate` читаются вчера и сегодня; явный `YYYY-MM-DD` задаёт именно день запроса, будущий день отвергается. `deviceId` — UUID подключения. Отсутствующий id означает все подключения. Изменение/пауза/удаление подключения во время HTTP отменяет его устаревший результат (`skipped`). HTTP выполняется вне UI-потока и блокировки основной БД; ручной и фоновый импорты сериализованы. В одноразовом запуске приложения poller не стартует.

Поля устройства: `id`, `label` (до 100 символов), `source` (`windows` или `android`), `endpoint` (HTTP loopback), `port`, `enabled`. `status` добавляет `capabilities`, `lastSuccess`, `lastError`, `records`, `deletedThrough`. `records` — число сохранённых дней именно этого подключения; ошибки сохраняют историю и последний успешный статус. Изменение источника, адреса или токена сбрасывает устаревший статус проверки; переименование и пауза его сохраняют. Максимум 8 подключений.

`capabilities`: `aggregate_app_durations`, `foreground_seconds`; `active_seconds` появляется только после данных AFK за запрошенные дни. Токен никогда не возвращается. `token` отсутствует — сохранить текущий, `""` — удалить, непустая строка — заменить. Максимум 1024 байта на токен и 4096 байт на весь защищённый JSON. Некорректное хранилище секретов отклоняется без перезаписи. Замена сначала сохраняет новый независимый слот, затем атомарно переключает ссылку в БД; прежний слот сохраняется до коммита. Незавершённые слоты очищаются следующим сохранением. При ошибке очистки после отключения возвращается `digital_activity_disconnected_secret_cleanup_failed`: подключение уже удалено, история сохранена.

## Событие календаря

Один `event` на UUID подключения и локальный день: `Активность · <label> · <duration>`, `time: null`. Суммарная длительность не превращается в непрерывный временной интервал. Нативные обычные действия редактирования, удаления, завершения и запуска таймера запрещены. Событие получает `readonly: true`, `source: activity_watch`, `activity: true`, `activity_summary: { foreground_seconds, active_seconds, apps }` в календарном mapper. `apps` — названия приложений и секунды; секунды сохраняют дробную часть. `active_seconds: null` означает отсутствие наблюдений AFK за этот день, включая пустой AFK bucket. Ноль означает, что наблюдения AFK есть, но пересечение с не-AFK пустое; это не измерение нажатий клавиш.

Windows foreground — объединение интервалов окон; последнее начавшееся окно получает пересекающийся отрезок (при равном старте — стабильный порядок имени приложения). Не-AFK — пересечение окон с объединёнными `not-afk` за вычетом `afk`. Границы обоих наборов участвуют в расчёте. Локальные границы каждого дня определяются отдельно через часовую зону устройства, включая смену смещения. Округление по отдельным отрезкам не применяется. События до 7 суток читаются с соответствующим lookback и обрезаются по выбранным дням; более длинное событие явно отклоняется. Нет foreground — нет нового пустого события. Недоступный/некорректный источник не удаляет старые записи.

Неизменный агрегат не меняет `version`/`updated_at` и не создаёт новую запись журнала. Изменённый агрегат проходит через существующий журнал `items`, без отдельной схемы синхронизации. При импорте `digital-activity-updated` отправляется только при изменении календаря; payload совпадает с результатом импорта. Очистка истории также отправляет это событие (см. ниже).

## Источник, приватность и границы проверки

HTTP: только `127.0.0.1`/`localhost`, без прокси/редиректов; timeout 5 секунд, ответ до 8 MiB, максимум 100000 событий (достижение лимита — ошибка). Параметры дат кодируются HTTP-клиентом, id bucket — сегментом URL.

Windows: ровно один `aw-watcher-window` / `currentwindow`; необязательный `aw-watcher-afk` / `afkstatus` с совпадающим непустым hostname. Android: ровно один `aw-android` / `currentwindow`, без вывода AFK по аналогии с Windows. Отсутствующие/дублирующиеся подходящие buckets — ошибка. `label` не влияет на выбор источника.

Windows data допускает только `app` и `title: "excluded"`. Android data допускает только `app` (обязательно), `package`, `classname`; title/URL/другие поля отвергаются. В БД, sync и диагностике остаются только агрегаты по `app`; package/classname, hostname, сырые события и заголовки не сохраняются. Проверки используют синтетический loopback API и изолированные SQLite/credential profiles.

Рефлексия теперь использует отдельные канонические записи и атомарный bundle/CAS.
Старые изменения расписания и поздняя зашифрованная очередь не стирают новые
вопросы и ответы. Контракт и миграция: [reflection-sync.md](reflection-sync.md).
Старые клиенты могут остановить получение неизвестного ключа, продолжая отправку;
двусторонняя совместимость со старой версией не заявлена. Перед production нужны
совместимые сборки всех устройств и физический round-trip. Номер 0.4.0 не
различает эти DEV-артефакты: проверять точный commit и хеш сборки.

## Очистка агрегатов

- `digital_activity_preview_erasure({deviceId, throughDate})` →
  `{deviceId, throughDate, count, deletedThrough}`. Дата включительна, не позже
  сегодняшней локальной даты. UUID может принадлежать удалённому подключению,
  если осталась его история или граница удаления.
- `digital_activity_erase_history({deviceId, throughDate, expectedCount})` →
  `{deleted, deletedThrough}`. UI передаёт count из preview. Несовпадение даёт
  `digital_activity_erasure_count_changed`, ничего не меняя.
- `digital_activity_status()` включает `deletedThrough: string|null` у устройств.
- Ошибки: `digital_activity_invalid_date`, `digital_activity_device_not_found`,
  `digital_activity_erasure_unsafe_record`. Ошибка целостности выбранных записей
  отменяет всю транзакцию, а не частично удаляет историю.

Выборка native проверяет канонический ID `digital-activity:<UUID>:<date>`, kind,
дату и теги источника. Обычный delete календаря остаётся запрещённым. Граница
`digital_activity_retention_v1` хранится отдельной sync-записью на UUID, растёт
по max даты и не редактируется generic UI setter. Сохраняется цельная версия
победившей записи; payload и её stamp не подменяются. Смена источника под новым
UUID не наследует запрет. Автоматический retention в днях пока не реализован.

Граница, tombstones, удаление items и счётчики меняются в одной транзакции.
Операция не ждёт HTTP и не читает секреты. Поздний результат HTTP, remote live
record с более новым stamp, merge checkpoint и conflict restore не возвращают
исключённые дни. Токен и локальное подключение не обязательны для очистки
оставшейся истории. При успехе отправляется `digital-activity-updated` с результатом
очистки, календарь обновляется и запрашивается обычная синхронизация.

Удаление касается активной проекции Cicada. ActivityWatch, старые архивы sync,
конфликты, резервные копии и физические следы SQLite/WAL не стираются.
