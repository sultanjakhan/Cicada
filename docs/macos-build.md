# Стабильная сборка для macOS

`Cicada.app` содержит интерфейс внутри приложения и запускается без Vite,
терминала или DEV. Идентификатор — `app.hanni.mvp`; обычная Hanni остаётся
отдельным приложением. Сборка предназначена для локальной установки на Mac.

Начиная с 0.3.18, подписанная сборка Apple Silicon из **Signed update candidate**
поддерживает автообновление. Её один раз устанавливают в `~/Applications/Cicada.app`;
следующие версии скачиваются и проверяются самим приложением. Проверка выполняется
при запуске, а пользовательский LaunchAgent `app.hanni.mvp.updates` — при входе
и раз в шесть часов, даже если Cicada закрыта. Установка откладывается, пока окно
используется или есть несохранённая работа. Автоматическая установка оставляет
приложение закрытым; ручная кнопка обновления перезапускает его.

Переходная версия 0.3.22 может скачать архив `Cicada.app.tar.gz` внутрь старого
`~/Applications/Hanni MVP.app`. При запуске 0.3.23 native startup переносит bundle
в `~/Applications/Cicada.app`, оставляет legacy symlink для уже загруженного
LaunchAgent, переоткрывает новый executable и обновляет plist на новый путь.

Обычная локальная сборка ниже не содержит ключ доступа к каналу. Для доставки
используйте `python3 scripts/package-update.py macos` в CI с существующими
секретами обновления. Tauri создаёт `.app.tar.gz`, подписанный постоянным ключом
Minisign. Подпись архива отличается от ad-hoc подписи самого `.app`.
Полный порядок публикации — [application-updates.md](application-updates.md).

Требуются Xcode Command Line Tools, Node/npm, Python 3 и Rust 1.98.1+.
Из чистого коммита независимого репозитория:

```sh
npm ci
npm run package:mac
```

Готовое приложение и manifest с коммитом, версией и SHA-256 файлов находятся
в `.local/mac-package/<commit>/`. Скрипт проверяет подпись и идентификатор;
сам он ничего не устанавливает и не запускает. Архитектура соответствует Mac,
на котором выполнена сборка. `tauri.macos.conf.json` включает локальную ad-hoc
подпись; Developer ID и нотариализация для внешнего распространения здесь
не настроены.

Ad-hoc подпись привязывает доверие Keychain к конкретной сборке: после обновления
сохранённый ключ может стать недоступен новой версии. Начиная с 0.3.20 все
обращения Cicada к Keychain запрещают системные диалоги, включая сохранение
подключения. Ошибка чтения запоминается до явного сохранения подключения или
перезапуска, поэтому фоновый обмен и проверка статуса не повторяют запрос.
При отсутствии доступа синхронизация приостанавливается с сообщением в настройках;
ключ не удаляется, ACL не ослабляется, локальные данные остаются на месте.
Постоянный доступ между обновлениями требует стабильной подписи приложения;
подпись Minisign защищает доставку архива, но не заменяет идентичность Keychain.

Для эксплуатационного восстановления после ad-hoc обновления одновременно
проверяйте обе границы доступа записи Keychain: trusted-app ACL для расшифровки
и partition ACL с актуальным CDHash приложения. Успешная проверка trusted-app
сама по себе не доказывает, что установленный бинарник может прочитать запись.
Если разрешён один системный запрос, заранее подготовьте оба изменения
метаданных и выполните единственный `SecKeychainItemSetAccess`. UI по умолчанию
должен оставаться запрещённым; глобально ослаблять ACL нельзя.

После восстановления проверяйте установленный бинарник через `--sync-check`,
затем подтверждайте свежим обменом на второй стороне синхронизации. До этих двух
проверок восстановление доступа не считайте завершённым.

Флаг `kSecUseAuthenticationUIFail` не подавляет диалоги файловой связки ключей
([Chromium, Apple FB16959400](https://chromium.googlesource.com/chromium/src/crypto/+/refs/heads/main/apple/scoped_keychain_user_interaction_allowed.cc)).
Поэтому до обращения применяется `SecKeychainSetUserInteractionAllowed(false)`;
приложение не включает взаимодействие обратно. Это политика только процесса Cicada.

Для скачивания из CI используется вложенный `Cicada-macos.zip`, созданный
через `ditto` с сохранением структуры и прав приложения. SHA-256 архива находится
в manifest; распакуйте этот архив перед установкой.

Приложение можно установить в `~/Applications/Cicada.app`. Рабочая база
release-версии находится в `~/Library/Application Support/app.hanni.mvp/`;
переменная `HANNI_MVP_DATA_DIR` в release игнорируется. Данные и ключи не входят
в `.app`, поэтому замена приложения не заменяет профиль.

Если DEV продолжает работать, подключайте стабильную версию как новое устройство
к существующей группе синхронизации: отдельный device ID и токен, тот же групповой
ключ. Не копируйте идентичность отправителя и его очередь в два одновременно
работающих профиля. Общие записи придут через сервер; настройки окна и локальные
предпочтения остаются отдельными. Перед переносом сохраняйте проверенную резервную
копию исходной базы.

Для подключения без открытия окна запустите исполняемый файл внутри `.app`
с `--configure-sync /absolute/path/to/private-pairing.json`. Файл содержит тот же
код подключения, который принимает экран настроек. Команда создаёт резервную
копию перед включением, сохраняет ключ в Keychain и ждёт завершения обмена.
`--sync-check` повторяет проверку уже сохранённого подключения без WebView.
Обе команды завершаются за 60 секунд: код 0 означает свежий успешный обмен без
ожидающей очереди или непрочитанных страниц; вывод содержит только статус.
Не запускайте эти команды параллельно с открытым приложением того же профиля.

`--minimized` запускает Mac-приложение со свёрнутым окном и значком в Dock;
разворачивание происходит по действию пользователя. `--background` оставляет
окно скрытым без значка Dock и предназначен для временных фоновых проверок.
Обычный запуск без аргументов открывает приложение как прежде.

Проверки сборки, запуска встроенного интерфейса, сохранения профиля и сетевого
обмена являются отдельными проверками. Во время фоновой проверки не выводите DEV
или тестовое окно поверх рабочего стола пользователя.

Основание: [Tauri App Bundle](https://v2.tauri.app/distribute/macos-application-bundle/)
и [локальная подпись](https://v2.tauri.app/distribute/sign/macos/).
