## Lifecycle and status ownership

Native review read supplies exact native taskId, taskRevision/resultVersion/content/reviewState/history. On awaiting_review or awaiting_dispatch the native list keeps the task active and disables manual Complete. Published/executor done does not alter completion; a publisher result remains labelled “результат источника”, not an immutable accepted AI result. Only native accepted appears in completed; accepted tasks leave Dashboard current work and remain in Tasks history. Rework uses the existing native atomic intent/comment/audit and awaiting_dispatch state; there is no executor dispatcher, running confirmation or live publication added. ACK triggers existing task-state-changed refresh. Conflicts and pending payloads remain handled by ff/c877.

Native review opt-in is a source composition/testing seam, not a production setting or profile permission. Preparation failures/403/no result fall back to the existing task card. Native content/history are not copied into manual workflow.result. c877 keeps immutable results/audit in its existing isolated component tables; the UI can display current result and audit versions/comments. Opening old immutable content by arbitrary resultVersion is not added here; old DB content remains retained. Existing source-only migration/sync/downgrade gates still apply.

Default native task completion/IDs/Jira readonly handling, Work/Personal split, imported personal project tags, Create/Start semantics and manual timer remain. Native list optimization now includes observation projection in its signature: unchanged refresh retains DOM/focus; actual report/review changes re-render. Read joins never mutate native rows in normal flow, preserving execution callbacks. Read failures leave native list available and disclose source availability. Imported records without matching binding are never re-keyed or merged with Jira/personal identities.
