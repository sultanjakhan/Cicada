# Hanni MVP

Приватная основа отдельного приложения-календаря: задачи и события, без проектов.
Новая история Git; старая Hanni и её данные остаются отдельно.

Tauri 2 · Rust · SQLite · JavaScript. Версия 0.1.1.

Репозиторий остаётся приватным. Публичная публикация и лицензия — отдельный этап.

## Что есть

- Неделя, месяц и список; фильтры задач, событий и завершённых записей.
- Один редактор справа с переключателем «Задача / Событие».
- Задачи с датой или без неё, завершение и возврат в работу.
- События на весь день или на время; длительность до 24 часов и переход через полночь.
- Изменение, удаление с подтверждением, защита несохранённого черновика внутри приложения.
- Светлое, тёмное и системное оформление; ручная резервная копия SQLite.

Повторения, напоминания, синхронизация и мобильная сборка пока не реализованы.

## Запуск на Windows

Нужны Node.js 22.12+, Rust 1.98+, Visual Studio C++ Build Tools и WebView2 Runtime.
Команды сборки выполняй в Developer PowerShell для Visual Studio с доступными `cl` и `link`.

```powershell
npm.cmd ci
npm.cmd run tauri dev
```

Самостоятельный исполняемый файл с встроенным интерфейсом:

```powershell
.\node_modules\.bin\tauri.cmd build --debug --no-bundle
.\src-tauri\target\debug\hanni-mvp.exe
```

Если задан `CARGO_TARGET_DIR`, файл будет в его подкаталоге `debug`.
macOS и Linux в этой версии не проверялись.

## Установка MVP и следующие сборки

Windows-приложение называется **Hanni MVP**. У него отдельный бирюзовый значок с буквами
MVP, ярлык, запись в списке установленных приложений и процесс `hanni-mvp.exe`.
Установщик работает для текущего пользователя, без замены обычной Hanni.

Собирай его из чистого коммита **этого** репозитория:

```powershell
npm.cmd run package:windows
```

Установщик и `manifest.json` появятся в `.local/windows-package/<commit>/`.
Манифест содержит версию, исходный commit и SHA-256 установщика и exe до упаковки.
Tauri меняет служебную метку внутри NSIS-пакета, поэтому хэш установленного exe отличается
от `unbundled_executable_sha256`; для проверки полученного пакета используй `installer_sha256`.
CI выполняет эту же команду и сохраняет пакет в GitHub Actions artifacts; репозиторий
и пакеты остаются приватными. Для следующего обновления используется новый пакет
из `hanni-mvp` с тем же идентификатором `app.hanni.mvp` и собственной базой.

Это локальная тестовая сборка без Authenticode-подписи и автообновления.
Хэши подтверждают соответствие пакету, но не заменяют подпись издателя.

Для работы над вёрсткой: `npm.cmd run dev`, затем `http://127.0.0.1:1420/?preview=1`.
Это явно помеченный предпросмотр с записями только в `sessionStorage` вкладки.
Он не проверяет SQLite и исключён из production-сборки. Обычная браузерная страница
без native IPC не подменяет базу браузерным хранилищем.

## Данные и резервные копии

Первый запуск создаёт пустую `calendar.db` в системном каталоге данных приложения
`app.hanni.mvp` (на Windows: `%APPDATA%\app.hanni.mvp`). Локальная таблица `items`
хранит тип записи, название, заметку, дату, время, длительность, отметку завершения,
версию и служебные даты. SQLite-транзакции и проверка версии защищают от перезаписи
более свежего изменения старой формой. Время календаря — местное время устройства.

«Настройки → Создать копию» сохраняет отдельный файл в подкаталоге `backups` этого
каталога. Копирование использует SQLite online backup и проверку целостности.
Чтобы восстановиться вручную, закрой все окна **Hanni MVP**, сохрани текущую базу
и её файлы `-wal`/`-shm` отдельно, затем помести выбранную копию как `calendar.db`
без старых sidecar-файлов рядом. Встроенного восстановления пока нет.

Для изолированной проверки debug-сборки можно задать `HANNI_MVP_DATA_DIR` —
абсолютный путь к отдельному тестовому каталогу. Release-сборка игнорирует эту переменную.
Старую Hanni и её каталоги приложение автоматически не читает и не изменяет.
Данные не отправляются в сеть; шифрование базы приложением не реализовано.

## Проверки

```powershell
npm.cmd test
npm.cmd run check:privacy
npm.cmd run build
cargo test --manifest-path src-tauri/Cargo.toml --locked
```

JS-тесты проверяют даты и DST, пересечения интервалов, сценарии редактора в JSDOM,
сбой сохранения, подтверждение удаления и форму IPC-запросов. Rust-тесты проверяют
валидацию, CRUD, конфликты версий, повторное открытие базы и резервную копию.
JSDOM не является проверкой живого WebView. Визуальная и ручная native-проверка
остаются отдельным этапом. CI выполняет тесты и собирает Windows executable.

Privacy guard проверяет текущие текстовые файлы на типовые личные данные и секреты;
базы, выгрузки и локальные настройки исключены из Git. Локальный JSON-список
дополнительных приватных строк можно передать через `--denylist` вне репозитория.
Guard выводит только путь, строку и тип находки. Он не доказывает отсутствие всех
секретов, не анализирует содержимое бинарников и не очищает историю Git.

## Структура

`src/app.js` — интерфейс; `dates.js` и `layout.js` — расчёты календаря;
`store.js` — граница native IPC; `src-tauri/src/lib.rs` — SQLite и команды приложения.
Личных профилей, предзаполненной базы, моделей и конфигурации старого приложения здесь нет.
